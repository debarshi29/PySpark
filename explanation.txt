from pyspark.sql import SparkSession
from pyspark.sql.functions import col

# Create Spark session
spark = SparkSession.builder \
    .appName("Streaming Event Join and Filter") \
    .getOrCreate()

# Define schemas
event_schema = "event_id STRING, participant_id STRING, event_type STRING, timestamp STRING"
participant_schema = "participant_id STRING, name STRING, category STRING"

# Read streaming data from events
events_stream = spark.readStream \
    .schema(event_schema) \
    .csv("input/events/")

# Read static participant data
participants_static = spark.read \
    .schema(participant_schema) \
    .csv("input/participants/participants.csv")

# Filter events for specific types (e.g., learning-related)
learning_events = ["Workshop", "Seminar"]
filtered_stream = events_stream.filter(col("event_type").isin(learning_events))

# Join filtered stream with participants
joined_stream = filtered_stream.join(participants_static, "participant_id", "left_outer")

# Write the result to console
query = joined_stream.writeStream \
    .outputMode("append") \
    .format("console") \
    .option("truncate", "false") \
    .start()

# Wait for termination
query.awaitTermination()

# Stop the Spark session
spark.stop()

3. Defining Schemas
python

Collapse

Wrap

Copy
event_schema = "event_id STRING, participant_id STRING, event_type STRING, timestamp STRING"
participant_schema = "participant_id STRING, name STRING, category STRING"
What: Specifies the structure (column names and types) of the input CSV files.
Why:
Structured Streaming requires an explicit schema for streaming sources like CSV to interpret data correctly and efficiently.
Without this, Spark would infer the schema on every micro-batch, which is slower and error-prone (e.g., mistaking a string timestamp for an integer).
How It Works:
Each schema is a string where each part (e.g., event_id STRING) defines a column name and its data type.
For simplicity, all columns are STRING, though timestamp could be a TIMESTAMP type with parsing.

What: Creates a streaming DataFrame that reads new data from the input/events/ directory.
Why:
This is the core of streaming—continuously processing new events as they’re added to the directory.
Simulates a real-time data feed (e.g., event registrations).
How It Works:
readStream: Marks this as a streaming source, unlike read for batch data.
.schema(event_schema): Applies the predefined schema to incoming CSV data.
.csv("input/events/"): Monitors the directory for new files or appended rows. Spark processes each addition as a micro-batch.

What: Joins the filtered streaming events with static participant data on participant_id.
Why:
Enriches events with participant details (e.g., name, category), making the data more useful.
Demonstrates a hybrid streaming-static operation.
How It Works:
filtered_stream.join: Joins the streaming DataFrame.
participants_static: The static DataFrame to join with.
"participant_id": The key column for matching (must exist in both DataFrames).
"left_outer": Keeps all rows from the streaming side (left) and adds matching participant data (or null if no match). This ensures no events are lost.
8. Writing the Stream

Wrap

Copy
query = joined_stream.writeStream \
    .outputMode("append") \
    .format("console") \
    .option("truncate", "false") \
    .start()
What: Outputs the joined streaming data to the console as new records arrive.
Why:
Provides real-time visibility into processed events, simulating a monitoring dashboard.
Easy to test without needing a persistent sink.
How It Works:
writeStream: Sets up a streaming sink.
.outputMode("append"): Outputs only new rows in each micro-batch (ideal for event logging; complete or update would be for aggregations).
.format("console"): Sends output to the terminal (could be file, memory, etc.).
.option("truncate", "false"): Prevents long values (e.g., timestamps) from being cut off in the display.
.start(): Launches the query and returns a StreamingQuery object to manage it.

What: Keeps the program running until manually stopped (e.g., Ctrl+C).

Streaming is continuous—without this, the script would exit immediately after starting the query.
How It Works:
Blocks the main thread, allowing Spark to process new data indefinitely.
The query object lets you interact with the running stream (e.g., stop it programmatically if needed).
